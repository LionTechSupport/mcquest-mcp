# MCQuest MCP v0.5 — Decisions

## D001 — Normal Presentation Budget

Status: APPROVED

Decision:
4000 characters is the actual normal presentation budget.

Implication:
Context expansion MUST consume the same budget.
`context_lines` MUST NOT create a response larger than 4000 chars
for normal calls.

---

## D002 — Absolute Ceiling

Status: APPROVED

Decision:
16000 characters is an absolute response ceiling.

No tool or parameter combination may produce >16000 chars.

---

## D003 — find_evidence total

Status: APPROVED

Decision:
`total` is the authoritative merged-stream total, or count-so-far when
collection is incomplete.

It MUST NOT use `min(code_count, docs_count)`.

---

## D004 — Read asymmetry

Status: APPROVED

Unranged read:
4000-char normal presentation budget.

Explicit range:
up to 16000 chars.

---

## D005 — No JSON output

Status: APPROVED

v0.5 remains text-only.

---

## D006 — No max_chars

Status: APPROVED

Do not add a per-call `max_chars` parameter in v0.5.

---

## D007 - 200-Character Line Clip

Status: APPROVED

Decision:
Per-line output MUST be clipped to 200 characters. A 20,000-char single
line must appear as at most 200 chars (pattern: `line[:199] + "…"`, the
existing `diagnostics._clip` precedent is the reference model).

Rationale:
Phase 1 measured a 20k-char single-line file producing ~5,000 tokens in
one response.

---

## D008 - Explicit Pagination Only

Status: APPROVED

Decision:
Pagination is explicit only. The server NEVER returns page 2 (or any
subsequent page) automatically. The model must explicitly request
continuation via `offset` / `start_line`. No automatic page sequence.

---

## D009 - Deterministic Ordering

Status: APPROVED

Decision:
Where applicable, results are ordered deterministically by
`(relative_path ASC, line ASC)` so that `offset` pages are stable and
non-overlapping across calls on a fixed working tree.

---

## D010 - Read Window Bounds

Status: APPROVED

Decision:
Read default window = 250 lines; explicit-range hard window = 1,000
lines (char-bounded): unranged reads use the 4000 normal budget,
explicitly ranged reads may use up to 16,000 chars (D004).

---

## D011 - Diagnostics Defaults

Status: APPROVED

Decision:
`mcquest_diagnostics` keeps its existing bounded model (per-line clip,
bounded `context_lines`, `max_diagnostics`, "shown (of N)") and gains an
aggregate budget. Defaults change to `max_diagnostics = 15` and
`context_lines = 5` (from 20/12). Worst settings must stay within the
16,000 ceiling.

Rationale:
Phase 1 measured default 20x12 = ~28.5k chars (~7.1k tokens) and worst
50x25 = ~80k chars (~20k tokens).

---

## D012 - pattern_audit Summary-First

Status: APPROVED

Decision:
`mcquest_pattern_audit` is summary-first by default: `[CATEGORY COUNTS]`
with counts + small samples per category. Full evidence for one category
is returned only on explicit request via an additive single-category
parameter (e.g. `category`), still under the budget.

Rationale:
Phase 1 measured 11 categories x 100 matches = ~80k chars (~20k tokens).

---

## D013 - find_evidence Merged-Stream Page Budget

Status: APPROVED

Decision:
For `scope="all"`, `max_results` is ONE shared page budget over the
merged code+docs stream. Per-scope counts are reported separately.
Combined with D003, this prevents the Phase 1 measured compound result
(2x the caller's apparent limit).

---

## D014 - No File-Backed Output in v0.5

Status: APPROVED

Decision:
No file-backed response artifacts. No generated report files written to
the target repository. Repository investigation is served by progressive
disclosure and bounded retrieval. (Artifacts may be revisited as a
FUTURE consideration only.)

---

## D015 - No Tool Renames or Deletions

Status: APPROVED

Decision:
All 17 existing tool names remain unchanged. No tool is renamed or
deleted. New parameters are additive only.
