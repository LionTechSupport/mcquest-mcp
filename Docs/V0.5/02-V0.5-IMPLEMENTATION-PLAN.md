# MCQuest MCP v0.5 — Implementation Plan

> Maps directly to the approved Token-Sparse Contract
> (`01-V0.5-CONTRACT.md`) and its binding clarifications
> (`05-V0.5-DECISIONS.md`). Do NOT redesign the approved architecture.
> One phase at a time, per `00-V0.5-MASTER.md` §9.
> Phases A–F were defined in the approved v0.5 design (Phase 2 contract).

## Phase A — Output Budget Infrastructure

Objective:
Create the single reusable budget mechanism and route the existing
formatter funnel through it (normal budget 4000, ceiling 16000,
line clip 200, atomic item emission, explicit `truncated` state,
summary-first compatibility). Do NOT change tool behavior.

Dependencies:
None.

Allowed files:
- src/mcquest_mcp/config.py (constants only)
- src/mcquest_mcp/formatting.py (OutputBudget + wrappers)
- tests/test_output_budget.py (new)

Prohibited files:
- all tools/*.py (no tool semantics changes in Phase A)
- server.py (no schema changes in Phase A)
- security.py, cli.py, pyproject.toml
- any existing test (only additive new test file)

Implementation tasks:
1. config.py: change `MAX_OUTPUT_CHARS` 80_000 -> 16_000; add
   `NORMAL_OUTPUT_CHARS = 4_000`, `LINE_CLIP_CHARS = 200`.
2. formatting.py: add `_clip_line(line, limit)`; add `OutputBudget`
   (fits/emit/add_line/with_header/finalize, atomic item cutoff,
   `truncated` state, trailing `[OUTPUT TRUNCATED: N characters omitted]`
   marker retained); reroute `truncate()` through the ceiling; reroute
   `numbered_lines()` through per-line clip + atomic emission; add
   `summary_block()` helper (used by Phases B+).
3. tests/test_output_budget.py: see `04-V0.5-TEST-PLAN.md` D–H + V(atomic).

Tests:
- Focused: tests/test_output_budget.py (4000 normal, 16000 ceiling,
  200 clip, atomic cutoff, summary-preservation, serialized bound).
- Regression: test_security_readonly.py::test_truncate_bounds_output
  (marker preserved), test_registration.py, test_discoverability.py.

Acceptance criteria:
- Every default call keeps <= 4000 chars once tools adopt the normal
  budget (Phase B+); formatter ceiling <= 16000 chars enforced now.
- No response can exceed 16000 chars (serialized invariant included).
- Existing marker text and numbered-lines prefix preserved.

Exit criteria:
- Focused tests pass; relevant existing tests pass; hard ceiling proven;
- STATE updated (Phase A = COMPLETE only with this evidence);
- CHANGELOG corrected/updated with verified facts only.

Documentation updates required:
- Docs/V0.5/03-V0.5-STATE.md (Phase A status + evidence)
- Docs/V0.5/06-V0.5-CHANGELOG.md (verified entry; the earlier false
  "Phase A COMPLETED" entry stays marked INCORRECT)
- Docs/V0.5/05-V0.5-DECISIONS.md (only genuinely new material decisions)
- Docs/V0.5/00-V0.5-MASTER.md (§3 Current Status update)

## Phase B — Reads (read_file, read_doc)

Objective:
Windowed reads. `read_file(path)` / `read_doc(path)` without `end_line`
return a bounded default window (default 250 lines) under the 4000-char
normal budget with `next_start_line` continuation; explicitly ranged
reads are honored up to the hard ceiling (16,000 chars, 1,000-line
window cap). Preserve the 2MB file guard.

Dependencies:
Phase A (OutputBudget).

Allowed files:
- src/mcquest_mcp/tools/files.py (read_file only)
- src/mcquest_mcp/tools/docs.py (read_doc only)
- src/mcquest_mcp/server.py (schemas/descriptions for read tools only)
- tests/test_read_file.py (new), tests/test_read_doc.py (new)

Prohibited:
- search/list/find/audit/context tool semantics
- security.py, cli.py, pyproject.toml
- no file-backed output, no format=json, no max_chars

Implementation tasks:
1. Derive default window end (start_line..min(total, start+249)).
2. Emit summary block: start_line, end_line, total_lines,
   next_start_line, has_more, truncated, budget.
3. Clamp explicit end_line to 1,000-line window and 16,000-char ceiling.
4. Route lines through numbered_lines + line clip (Phase A).

Tests:
- `04-V0.5-TEST-PLAN.md` O (window tests), L (next_start_line), D
  (ceiling), F (clip via read paths).

Acceptance:
- Unranged read <= 4000 chars; explicit range <= 16000 chars;
- next_start_line = end_line + 1; has_more consistent;
- 2MB guard intact; >1,000-line explicit window clamped.

Exit criteria:
- Focused tests + relevant regression green; STATE updated;
- read_file(path) no longer silently dumps a whole file.

Documentation updates:
- STATE (Phase B), CHANGELOG (verified), MASTER §3.

hard cap 300) of paths, and explicit `offset` continuation.
Deterministic ordering; never dump thousands of paths.

Dependencies:
Phase A (output budget). Phase B state unchanged.

Allowed:
- src/mcquest_mcp/tools/files.py (list_files, find_files)
- src/mcquest_mcp/tools/docs.py (list_docs)
- src/mcquest_mcp/server.py (schemas/descriptions)
- tests/test_list_*.py, tests/test_find_files.py (new/extended)

Prohibited:
- search/audit/diagnostics semantics; security.py; cli.py

Implementation tasks:
1. Add summary block: total, count, aggregate metadata, returned.
2. Add `offset` parameter (default 0).
3. Bound collection (offset + <hard cap>) and presentation (4000
   default page).

Tests:

  (next_offset), M (totals), V (601-file fixture, 304-doc fixture).

Acceptance:
- Default call <= 4000 chars; offset pages correct; counts honest;
- deterministic ordering across calls.

Exit criteria:
- Focused tests green; regression green; no directory listing dump.

Documentation updates:
- STATE, CHANGELOG, MASTER §3.

## Phase D — Search / Imports / Usage / Evidence

Objective:
Search-first contract for `search`, `search_docs`, `find_imports`,
`find_usages`, `find_evidence`, and `phase_context` query mode:
summary (total, files affected) + small evidence page (default
max_results=50) + explicit `offset`; per-line clip 200; deterministic
`(relative_path ASC, line ASC)` ordering; add the missing 2MB guard to
find_imports/find_usages; find_evidence uses ONE shared merged-stream
page budget with per-scope counts and an authoritative `total` (never
min(code_count, docs_count)).

Dependencies:
Phase A (and B/C for consistent shape).

Allowed:
- src/mcquest_mcp/tools/search.py, docs.py, imports.py, context.py
- src/mcquest_mcp/server.py (schemas/descriptions)
- tests/test_search.py, test_search_docs.py, test_find_imports.py,
  test_find_usages.py, test_find_evidence.py (new/extended)

Prohibited:
- include/exclude_pattern additions (not approved for v0.5)
- vector/semantic search; regex-engine changes; security.py

Implementation tasks:
1. Reuse search collection; add summary + offset paging + 200-clip.
2. Add 2MB file-size skip to find_imports/find_usages (missing guard).
3. find_evidence: merged-stream collection, per-scope counts,
   authoritative total, one shared page budget; deterministic ordering.

Tests:
- `04-V0.5-TEST-PLAN.md` I–N, R, F, V (search corpus).

Acceptance:
- Default search <= 4000 chars; `context_lines` never bypass 4000;
- honest totals + `collection_complete`/`total_known`;
- find_evidence never returns separate-scope compound results.

Exit criteria:
- Focused tests + full regression green.

Documentation updates:

## Phase E — Analysis (pattern_audit, diagnostics) / project/git/phase

bounded context, "shown (of N)") under an aggregate budget with adjusted
defaults (max_diagnostics 20->15, context_lines 12->5); lightweight
summary-first headers for project/git/compare/phase tools without
needless pagination.

Phase A (+D where search/evidence/phase context are governed).

Allowed:

  test_project*.py, test_git_context.py (new/extended)
