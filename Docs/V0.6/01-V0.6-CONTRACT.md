## Binding Premises (Phase 0 baseline)

P001 — Central objective. v0.6 must be judged against:

> "Can a coding agent reliably use MCQuest as its primary repository-evidence
> interface without unnecessary shell fallback, without treating incomplete
> evidence as complete, and without consuming unnecessary context?"

P002 — Repository evidence → prefer MCQuest. When an MCQuest tool provides
the required repository evidence, prefer it over an equivalent shell command
(e.g. grep, Select-String, Get-ChildItem). The existing server instructions
already state this preference.

P003 — Execution/runtime → shell is appropriate. Running tests, builds,
typechecks, reading live runtime/generated output, and inspecting process
state are execution/runtime workflows. Shell use there is NOT a tool-selection
failure.

P004 — Incomplete evidence is not complete. `truncated=true`, `has_more=true`,
`next_offset`, `next_start_line`, `collection_complete=false`, and
`returned < total` all mean the response is a page, not the whole. The agent
MUST continue via explicit `offset` / `start_line` or state the evidence is
incomplete. The agent MUST NOT claim "I have the complete evidence" when the
response explicitly indicates truncation or continuation.

P005 — `collection_complete=true` means the total count is known (two-pass
honest counts), NOT that all items were delivered. `has_more=true` means more
pages exist. Both may be true simultaneously; that is not a contradiction.

P006 — Phase 0 scope discipline applies. v0.6 must not introduce semantic/
vector search, embeddings, AI summarization, indexing, execution tools,
generated-artifact access, broad language support, or new security surfaces
unless explicitly authorized by the user.

P007 — Bounded-output model is permanent. 4000 / 16000 / 200 invariants
(see `00-V0.6-MASTER.md` §4) govern every tool response.

P008 — No partially-implemented evidence. Legacy tools that surface bounded
pages MUST expose the same truncation/continuation metadata as the v0.5
Phase A–D tools, or their descriptions must state how boundedness is applied.

## Open Questions (resolved by Phase 1 authorization, 2026-09-14)

Q001 — pattern_audit v0.5-style summary-first output + additive `category`:
**RESOLVED — APPROVED.** Implemented in Phase 1: summary-first default
(`[SUMMARY]` + `[CATEGORY COUNTS]` + up to 2 samples/category) under the
4,000-char budget; single-category expansion via `category` under the
16,000-char ceiling; enum-validated; legacy `categories` preserved.

Q002 — find_imports / find_usages / find_evidence language-scope wording:
**RESOLVED — APPROVED (discoverability only).** Implemented in Phase 1:
`find_usages` states TS/TSX/JS/JSX-only scope; `find_evidence` states the
code-stream language set and semantics. Language support was NOT broadened.

Q003 — Phase F acceptance harness carry-forward:
**RESOLVED — APPROVED.** Implemented in Phase 1 as `tests/test_token_sparse.py`
(default ≤4000 where a normal contract exists; worst-case ≤16000 raw AND
serialized across every applicable registered tool).

Phase 1 required no further contract changes; v0.5 invariants in
`Docs/V0.5/01-V0.5-CONTRACT.md` remain in force.
