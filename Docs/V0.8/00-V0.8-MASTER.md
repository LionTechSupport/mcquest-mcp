## 1. Purpose

V0.8 defines a proposed extension layer to improve the MCQuest MCP from a repository-intelligence server into a more practical application-audit and review-companion assistant.

The proposed V0.8 additions are:

- `mcquest_find_ui_text`
- `mcquest_ui_contract_audit`
- `mcquest_doc_gap_audit`
- `mcquest_feature_impact_audit`

These are intended to support:

- user-facing string discovery in UI files
- shared-component contract validation
- doc-to-code drift detection
- feature-level impact analysis
- read-only audit and review support (no write-enabled project operations)

The design remains read-only and evidence-first.

## 4. V0.8 Scope Summary

V0.8 is intended to add a dedicated audit layer above the existing MCQuest evidence tools.

### Proposed tool layer

#### 4.1 `mcquest_find_ui_text`

Purpose:

- scan TS/TSX/JS/JSX for user-visible text candidates (lexical heuristics only)
- classify text per the fixed enum `localizable` | `brand` | `admin-only` | `decorative` | `unknown`; emittable in V0.8: `decorative` (no ASCII letter) and `unknown` (letter-bearing, while the brand-token and admin-marker lists are unrecorded) — DEC-032
- return exact file/line evidence with low-noise ordering

Scope (decision D2 / DEC-015): lexical-only UI-text candidate detection and classification. Parser-grade and semantic UI classification remain RESERVED and NOT AUTHORIZED (Phase 3 lane, `Docs/V0.7/02-V0.7-PLAN.md` §Future Phases).

Extraction boundary (DEC-026): candidates are quoted string literals and template-literal static segments only (the approved `mcquest_find_strings` primitive). JSX text nodes between tags are NOT covered, and comments are not a candidate source; `include_brand` is deferred; the `brand` classification is not emittable until a token list and owner are recorded, and `localizable` is not emittable until an evidence rule is recorded (never inferred by elimination — DEC-032). See `01-V0.8-CONTRACT.md` section 2.1.

#### 4.2 `mcquest_ui_contract_audit`

Purpose:

- detect contract drift between shared UI components and their call sites
- identify missing props, mismatched signatures, stale modal contracts, and similar issues
- report evidence without performing any fix

#### 4.3 `mcquest_doc_gap_audit`

Purpose:

- compare docs and implementation for stale, missing, or conflicting references
- identify documentation drift and likely follow-up items
- support doc quality control for proposals and feature tracking

#### 4.4 `mcquest_feature_impact_audit`

Purpose:

- answer: “what is affected if this change or feature is modified?”
- connect a file, symbol, or screen to related docs, locale keys, and implementation references
- produce a structured review list for human decision making

## 5. V0.8 Design Principles

1. Read-only by default
2. Evidence-first output
3. Small specialized tools, not one giant “everything” tool
4. Deterministic bounded output
5. Clear separation between evidence, analysis, and recommendation
6. No write operations in the target repository
7. No implicit project mutation or side effects
8. Recommendations are review checklists only, never presented as fact
9. Client interoperability through stable metadata, not imitation of client-native tools

---

## 6. Non-Negotiable Boundaries

The V0.8 layer must not:

- modify repository files
- edit user docs or code
- commit or push
- perform repository mutation
- claim a result without evidence
- infer business decisions without evidence and explicit scope
- present AI-generated recommendations as fact without evidence
- introduce any new search index, parser dependency, or embedding surface beyond existing primitives (decision D6 / DEC-019)
- overlap with the reserved Phase 3 UI-string classification work; only the narrow lexical lane authorized for `mcquest_find_ui_text` (decision D2 / DEC-015)
- emit values or implement inputs whose prerequisites are not recorded: the `localizable`, `brand`, and `admin-only` classifications, the `missing_doc` and `status_mismatch` issue types, `risk` values, consistency rows, the `feature_scope` input, and the `include_admin`/`include_brand` filters (removed/deferred — DEC-024/DEC-025/DEC-026/DEC-030/DEC-031/DEC-032)
- claim JSX text-node coverage or comment filtering for `mcquest_find_ui_text` (DEC-026)
- return a non-empty-looking empty result for rejected or invalid input (DEC-027)
- change an approved evidence→label mapping or lexical evidence rule without revised fixtures and explicit approval (DEC-028/DEC-029)
