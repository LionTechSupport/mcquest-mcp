## 4. Known Constraints

The following constraints are recognized in the planning record:

- V0.8 must not overlap with reserved Phase 3 work; only the narrowly authorized lexical lane for `mcquest_find_ui_text` is in scope (DEC-015)
- parser-grade and semantic UI classification remain unauthorized
- the additional tools must remain narrow and evidence-first
- the architecture must not devolve into a giant all-in-one tool
- all V0.8 tools are read-only; no document-correction or write authority exists under V0.8
- no new search index, parser dependency, embedding surface, or broad-language expansion (DEC-019)
- `mcquest_ui_contract_audit` completeness is full-scan two-pass; only `mcquest_doc_gap_audit` and `mcquest_feature_impact_audit` use the capped-scan model (DEC-016/DEC-022); `mcquest_doc_gap_audit` bounded-scan parameters are `MAX_ENUMERATE_FILES = 2000` / `MAX_FILES_ANALYZED = 500`, `total` counts findings within the bounded scan only, and the incomplete-collection NOTE appears only when a cap is actually hit (DEC-033)
- `mcquest_feature_impact_audit` uses the same capped-scan model (DEC-016/DEC-022); its `include_docs`/`include_locales` inputs are optional booleans defaulting to `true` (DEC-034) and its bounded-scan parameters are `MAX_ENUMERATE_FILES = 2000` / `MAX_FILES_ANALYZED = 500`, with `total` counting findings within the bounded scan only and the incomplete-collection NOTE appearing only when a cap is actually hit (DEC-035)
- comments and JSX text nodes are out of scope for `mcquest_find_ui_text`; `include_brand` and `include_admin` are removed/deferred; `localizable`, `brand`, `missing_doc`, `conflicting_reference`, `admin-only`, `status_mismatch`, and `risk` values (and the `feature_scope` input) are NOT EMITTABLE/implementable until item-specific decisions are recorded (DEC-025/DEC-026/DEC-030/DEC-031/DEC-032/DEC-033); the emittable `mcquest_find_ui_text` labels are `decorative` (no ASCII letter) and `unknown` (letter-bearing; reason names the missing brand/admin lists — DEC-032); `mismatched_usage` and `signature_drift` severity mappings are recorded as `warning` (DEC-031); `mcquest_doc_gap_audit`'s only currently emittable issue type is `stale_reference`, whose carriers are inline backtick-span content and path-like tokens with a recognized extension (prose identifiers are never candidates by identifier shape alone — DEC-033)
- consistency rows are not emitted until a new row type is approved (DEC-024)
- out-of-root and invalid inputs are rejected explicitly, never silently returned as empty results (DEC-027)

## 6. Record of Intent

The purpose of V0.8 is to add a focused audit layer that helps agents understand:

- what user-facing text exists,
- whether UI contracts are stable,
- where docs may be stale,
- and which files/features are likely affected by a change.

This is useful for real-world app maintenance and project documentation, but it must be introduced carefully and only with explicit approval.
