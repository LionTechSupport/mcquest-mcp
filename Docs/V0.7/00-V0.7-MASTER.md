## 2. Authority Order

When documents appear to conflict, higher wins:

0. **Repository reality + executable test evidence** (always highest)
1. User's explicit instruction in the current task
2. `03-V0.7-STATE.md` (living checkpoint)
3. `01-V0.7-CONTRACT.md` (normative specification)
4. `04-V0.7-TEST-PLAN.md` (test/benchmark contract)
5. `05-V0.7-DECISIONS.md` (approved + baseline decisions)
6. `02-V0.7-PLAN.md` (plan)
7. `06-V0.7-CHANGELOG.md` (historical log)

Rules:

- Never use a lower-priority document to silently override a higher one.
- Never trust the CHANGELOG for current state — it is historical only.
- Never infer "implemented" from a plan, a prompt, a changelog entry, a
  previous Cline response, or the mere existence of a file.
- "Implemented" requires repository evidence AND relevant passing tests.
- "Measured" requires a recorded benchmark observation with tool calls,
  responses, and measurement fields — never a summary claim alone.
- If a document disagrees with repository reality, repository reality wins;
  report the discrepancy; do NOT silently reconcile the document.

## 4. Non-Negotiable Invariants (carried forward from V0.5/V0.6)

The following MUST remain true through V0.7 Phase 0:

- normal presentation budget ≤ 4000 characters
- absolute response ceiling ≤ 16000 characters
- per-line clip ≤ 200 characters
- explicit pagination only (no automatic page 2)
- deterministic ordering `(relative_path ASC, line ASC)` where applicable
- root confinement preserved
- ignored-directory / ignored-extension policy preserved
- symlink safety preserved
- read-only behavior preserved
- no writes to the target repository
- text output only
- no new security surface
- no `_meta`, no file-backed response artifacts, no `format=json`
- Phase 0 makes no `src/`, `tests/`, `Docs/V0.5/`, or runtime-config edits
