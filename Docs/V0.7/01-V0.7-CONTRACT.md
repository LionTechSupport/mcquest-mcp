## 1. Binding Premises (carried from V0.6 P001–P008)

P001 — Central objective (V0.7 Phase 0 framing). V0.7 Phase 0 must answer:

> "When Cline works in this repository, does it select MCQuest as its primary
> repository-evidence interface without unnecessary shell fallback, without
> treating incomplete evidence as complete, and without consuming unnecessary
> context?"

P002 — Repository evidence → prefer MCQuest. When an MCQuest tool provides
the required evidence, prefer it over shell (grep, Select-String,
Get-ChildItem). Server instructions already state this preference.

P003 — Execution/runtime → shell is appropriate. Tests, builds, typechecks,
live runtime/generated output, and process state are execution workflows.
Shell use there is NOT a tool-selection failure.

P004 — Incomplete evidence is not complete. `truncated=true`,
`has_more=true`, `next_offset`, `next_start_line`,
`collection_complete=false`, `returned < total` all mean the response is a
page, not the whole. Continue via explicit `offset`/`start_line` or state
the evidence is incomplete. MUST NOT claim complete evidence otherwise.

P005 — `collection_complete=true` means the total is known (two-pass honest
counts), NOT that all items were delivered. `has_more=true` means more pages
exist. Both true simultaneously is not a contradiction.

P006 — Phase 0 scope discipline. No semantic/vector search, embeddings, AI
summarization, indexing, execution tools, generated-artifact access, broad
language support, or new security surfaces. No MCP change in Phase 0.

P007 — Bounded-output model is permanent. 4000 / 16000 / 200 invariants
(see `00-V0.7-MASTER.md` §4) govern every tool response.

P008 — No partially-implemented evidence. Bounded legacy tools MUST expose
truncation/continuation metadata or state how boundedness is applied.

P009 — Phase 0 is read-only and threshold-free. Observations only; no
thresholds, no implementation-complete markings, no edits to `src/`,
`tests/`, `Docs/V0.5/`, or runtime configuration.

## 2. Benchmark Task Classes (normative)

Phase 0 MUST cover at least one benchmark task per class. Each run records
the measurement fields in §3.

| ID | Task class | Definition | Representative MCQuest-primary tool(s) |
|---|---|---|---|
| C01 | repository search | Locate a symbol/string across source with bounded paged search | `mcquest_search` |
| C02 | targeted file reads | Read an exact file section via bounded line ranges + continuation | `mcquest_read_file` |
| C03 | docs evidence | Locate a statement in docs, then read the targeted section | `mcquest_search_docs` → `mcquest_read_doc` |
| C04 | imports/usages | Trace imports/references, honoring TS/TSX/JS/JSX-only scope | `mcquest_find_imports` / `mcquest_find_usages` |
| C05 | bounded/incomplete evidence | Page a truncated response to completion or explicit incomplete stop | any paged tool (search, read_file, read_doc, list_files, list_docs) |
| C06 | cross-document evidence | Reconcile/diff evidence across two or more documents/phases | `mcquest_phase_context` / `mcquest_compare_phase` / `mcquest_find_evidence` |
| C07 | runtime/generated artifacts | Request for generated/runtime output (pytest cache, `__pycache__`, `.git`, build output) redirected to execution workflow | shell (correct); MCQuest rejection/exclusion is the correct MCQuest-side signal |
| C08 | tests | Run the executable suite or focused subset | shell `uv run pytest` (correct per P003) |
| C09 | build/typecheck | Run a build or typecheck workflow | shell (correct per P003) |
| C10 | process execution | Inspect live process/server state or restart a stale endpoint | shell / host process management (correct per P003) |
| C11 | stale/failed evidence-tool recovery | Detect stale/failed/disconnected endpoint, classify lifecycle vs. defect, recover via restart/retry | shell restart + MCQuest re-verification (cf. V0.6 T1–T6 precedent) |

V0.6 baseline context: Phase 0 Ledger tasks A–J and live T1–T6 in
`Docs/V0.6/03-V0.6-STATE.md` and `Docs/V0.6/06-V0.6-CHANGELOG.md`.

## 3. Measurement Fields (normative)

Every benchmark task run MUST record all fields below. Ratios are aggregate.

| Field | Definition | Allowed values |
|---|---|---|
| primary-tool correctness | Was the first evidence tool the correct primary for the task class? | `correct` / `incorrect` + named tool |
| MCQuest-primary rate | Aggregate: fraction of repository-evidence runs (C01–C06) with MCQuest primary | ratio `n/N` (computed) |
| operation correctness | Were operation/parameters correct (path, pattern, range, offset, category, phase id)? | `correct` / `incorrect` + detail |
| unnecessary shell fallback | Shell where MCQuest provides the evidence? (P003 C08–C10 excluded) | `yes` / `no` + command |
| broad-read rate | Aggregate: fraction of runs with broad/whole-doc retrieval where targeted search→read or paging existed | ratio `n/N` (computed) |
| duplicate evidence | Same evidence re-fetched without continuation/new-information reason? | `yes` / `no` + detail |
| completeness awareness | On bounded/incomplete response: continued correctly or explicitly stated incompleteness (P004/P005)? | `correct` / `incorrect` + signals |
| recovery | On stale/failed/suspect-empty evidence: detected, correctly classified, recovered? | `correct` / `incorrect` / `n/a` + detail |
| execution-boundary correctness | Repository-evidence vs. execution/runtime boundary honored (P002 vs. P003)? | `correct` / `incorrect` + detail |
| context efficiency | Minimum-sufficient path used (targeted search→read; paging only as needed)? | `efficient` / `overbroad` + sizes/calls |

Claiming "complete evidence" while `truncated=true`, `has_more=true`,
`next_offset`/`next_start_line` present, `collection_complete=false`, or
`returned < total` is `completeness awareness = incorrect` by definition.
