## Stage 1 — Implementation (IMPLEMENTED 2026-09-17 — DEC-010)

`mcquest_search` extended with an optional `exclude_pattern` regex that
filters matching **lines** out of search results. Approved per Stage 1
plan + the user's single required test adjustment (fixed baseline
compatibility check).

- **Contract:** new optional `exclude_pattern: str = ""` on
  `search_text` and the `mcquest_search` registration. Semantics:
  - a line is a result iff it matches `pattern` AND NOT `exclude_pattern`
    (exclude wins on overlap);
  - compiled with the SAME flags as `pattern` (honors `case_sensitive`);
  - applied in BOTH the pass-1 count and the pass-2 page so `total` /
    `files_affected` are post-exclusion and paging stays truthful and
    contiguous;
  - composes with `file_pattern` (glob include + line exclude both);
  - context rendering around a kept match is unchanged (excluded lines
    are not matches; they do not alter a surviving match's context
    window);
  - the summary echoes `EXCLUDE: <regex>` ONLY when non-empty, so the
    default output is byte-for-byte unchanged;
  - invalid `exclude_pattern` → `ValueError("Invalid exclude_pattern
    regex: …")` (distinct from the include-pattern error);
  - `""` (default) = no exclusion (empty string only; whitespace-only
    strings are real regexes).
- **Backward compatibility (required gate):** fixed baseline
  `BASELINE_OUTPUT` (503 bytes) captured from the pre-change build via
  `_capture_baseline.py` with the exact fixture; `search_text(...)`
  without `exclude_pattern` reproduces it byte-for-byte
  (`test_baseline_output_unchanged_without_exclude`). The
  omitted-vs-explicit-`""` equality test is also present.
- **Files changed:**
  - `src/mcquest_mcp/tools/search.py` — signature, exclude compile +
    `_keeps()` predicate used by both passes, `EXCLUDE` echo, docstring;
  - `src/mcquest_mcp/server.py` — `mcquest_search` registration gains
    `exclude_pattern` with description; tool description notes it;
  - `tests/test_search.py` — `BASELINE_OUTPUT` constant + 13 new tests
    (baseline, omitted-vs-empty, filtering, overlap, zero-total page,
    paging contiguity, file-pattern composition, case sensitivity,
    invalid regex, unchanged context, `EXCLUDE` echo, 4k budget);
  - `tests/test_discoverability.py` — new
    `test_search_exclude_pattern_parameter_described`;

    `exclude_pattern="zetaSym"` (rare token exercising both passes under

## Stage 3 — Implementation (IMPLEMENTED 2026-09-17 — DEC-012)

`mcquest_locale_inspect`, a new read-only JSON locale-inspection tool,
implemented exactly per the user's Stage 3 authorization with the
approved D-1..D-7 decisions as the binding design baseline (including

- **Contract implemented (`src/mcquest_mcp/tools/locales.py`):**
  - JSON only (`.json` files under the bounded scope; `file_pattern`
    matches the basename; a direct single-file `path` is accepted).
  - D-1 duplicate-preserving parse: `json.loads(text,
    object_pairs_hook=_Pairs)` — every object a `_Pairs` list of
    `(key, value)` pairs (single source of truth; arrays plain lists,
    scalars native). One deterministic walk per file performs, at each
    effective object node, a syntactic DUP scan over the FULL pair list
    and an effective last-value mapping that alone drives structure
    counts, casefold collisions, identity paths and recursion; shadowed
    earlier values are never traversed or reported (the shadowing event
    IS a DUP; an effective node's own repeats ARE reported).
  - Identity = `{()}` + the path of every scalar-valued key/array index;
    container-valued keys contribute their children; arrays positional,
    never merged/deduplicated (`"0"` vs `[0]` distinct everywhere);
    root object/array/scalar semantics; shape differences surface in
    STRUCTURE rows, never MISSING/EXTRA (documented limitation).
  - Row kinds: STRUCTURE (root shape + per-node effective key/array
    counts, typed-path order), COLLISION (casefold groups at an
    effective node, e.g. `Straße`/`strasse`), DUP (`(N occurrences;
    last value kept)`), MISSING/EXTRA (identity path-set diff vs the
    reference; MISSING = in reference, absent in target; EXTRA = in
    target, absent in reference; eligibility = reference valid AND
    target structurally complete), ERROR (READ/DECODE/OVERSIZED →
    not-examined; DEPTH/PARSE/IDENTITY → findings-unknown; single row,
    working set discarded, no partial identity).
  - D-2 bounds kept exactly: 2000 / 500 / 200 / 100000 / 8000000 /
    64000000 / 3000 / 5000 / 2000000 / 1000000; raw-text depth
    pre-check before `json.loads`; identity bounds charged atomically
    at commit (candidate-path construction transient and uncharged).
  - D-3: `reference=""` → structure/collision/duplicate inspection only
    (REFERENCE_STATUS: none; no default locale inferred); reference
    failures disable comparisons globally (REFERENCE_LIMITED) and never
    enter ERROR_EVENTS; a reference file also scanned as a target keeps
    both roles separate (empty diff against itself, no double count).
  - D-4/D-6/D-7: deterministic byte-order files; typed-path row key
    (file bytes first; rows by typed path then rank STRUCTURE0
    COLLISION1 MISSING2 EXTRA3 DUP4 ERROR5); per-file cap (3000) before
    global cap (5000); counting mode after global exhaustion (later
    files fully analyzed, nothing materialized, exact ordinary
    cardinalities added to FINDINGS_OMITTED); error rows consume cap
    slots (ERROR_ROWS_OMITTED = Σ ERROR_EVENTS − collected error rows);
    enumeration completeness conservative (exactly-at-cap ⇒ incomplete;
    unreadable directory / undecodable path component ⇒ incomplete;
    files_not_examined_unknown + ENUM_LIMIT / ENUM_REASON, no exact
    totals when incomplete); DISCOVERED = EXAMINED + files_not_examined
    partition when complete; collection_complete=false whenever
    comparisons are disabled or the scan is incomplete.
  - D-5 display: JSON-quoted key segments, `[i]` indices attaching
