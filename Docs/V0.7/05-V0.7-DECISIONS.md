## DEC-012 — Stage 3 implemented: `mcquest_locale_inspect` JSON locale inspection (2026-09-17)

Status: APPROVED (implementation authorized by the user with D-1..D-7 as
the binding design baseline; executed and verified). **CLOSED 2026-09-17**
on the reported read-only final audit: PASS WITH CONCERNS, **no blocking
D-1–D-7 defects** reported; concerns C1–C4 remain non-blocking and are
NOT authorized work (no fixes applied). Stages 4–5 and Phase 3 remain
NOT AUTHORIZED. No commit or push.

Stage 3 of the revised V0.7 additive plan is implemented and tested:

- New read-only tool `mcquest_locale_inspect(path=".", reference="",
  file_pattern="*.json", max_results=50, offset=0)` in
  `src/mcquest_mcp/tools/locales.py`; registered in `server.py` (19
  tools) with an instructions mention. JSON only (`.json`;
  `file_pattern` on the basename).
- **D-1:** duplicate-preserving parse — every JSON object becomes a
  `_Pairs` list of `(key, value)` pairs via `object_pairs_hook` (single
  source of truth; arrays plain lists, scalars native). One deterministic
  walk per file: at each effective object node a syntactic DUP scan over
  the FULL pair list (all occurrences, source order) and an effective
  last-value mapping that alone drives structure counts, casefold
  collisions (`Straße`/`strasse` collide), identity paths and recursion.
  Shadowed earlier values are never traversed or reported (the shadowing
  event itself IS a DUP; an effective node's own repeats ARE reported).
  Identity = `{()}` + scalar-valued key/index paths; container-valued
  keys contribute children; arrays positional, never merged; root
  object/array/scalar semantics; shape differences surface in STRUCTURE
  rows, never MISSING/EXTRA (documented limitation).
- **D-2:** raw-text depth pre-check before `json.loads`; approved limits
  kept exactly (MAX_ENUMERATE_FILES 2000, MAX_LOCALE_FILES 500,
  MAX_JSON_DEPTH 200, MAX_EXACT_PATHS_PER_FILE 100000,
  MAX_EXACT_BYTES_PER_FILE 8000000, IDENTITY_UNITS_MAX 64000000,
  MAX_LOCALE_FILE_ROWS 3000, MAX_LOCALE_ROWS 5000, MAX_FILE_BYTES
  2000000, MAX_PARSE_NODES_PER_FILE 1000000). `MAX_PARSE_NODES_PER_FILE`
  is a documented invariant guard (node count provably ≤ 1,000,000 under
  the 2 MB cap), NOT an RSS or parse-allocation ceiling. Identity bounds
  charged atomically at commit; an over-budget commit rejects and
  discards the working set (no partial identity; candidate-path
  construction transient and uncharged).
- **D-3:** MISSING = present in reference, absent in target; EXTRA =
  present in target, absent in reference; comparisons run only when the
  reference is valid and the target is structurally complete; failed or
  partially flattened targets produce only ERROR rows; reference-role
  failures disclosed via REFERENCE_STATUS / REFERENCE_LIMITED and never
  double-counted into ERROR_EVENTS; `reference=""` means
  structure/collision/duplicate inspection only — no default locale is
  ever inferred.
- **D-4/D-6/D-7:** FINDINGS_OMITTED exact over complete+eligible files
  only (disabled comparisons never counted as omitted);
  FINDINGS_UNKNOWN for depth/parse/identity failures;
  files_not_examined for READ/DECODE/OVERSIZED and the beyond-cap tail;
  conservative enumeration completeness (exactly-at-cap ⇒ incomplete;
  files_not_examined_unknown + ENUM_LIMIT / ENUM_REASON, no exact
  totals); deterministic file order (relative-path UTF-8 bytes) and
  typed-path row order with rank STRUCTURE0 COLLISION1 MISSING2 EXTRA3
  DUP4 ERROR5 (typed-path order dominates rank); per-file cap before
  global cap; counting mode after global exhaustion (later files fully
  analyzed, nothing materialized, exact cardinalities added to
  FINDINGS_OMITTED); error rows consume cap slots with ERROR_ROWS_OMITTED
  disclosure; collection_complete=false whenever comparisons are
  disabled or the scan is incomplete (zero omitted findings never
  implies comparisons were performed).
- **D-5:** JSON-quoted key segments (`json.dumps`,
  ensure_ascii=False), `[i]` index segments attaching directly
  (`"menu"[0]."label"`), `<root>` root; no mid-path abbreviation; the
  only clipping is the renderer's 200-character atomic line clip with
  its explicit marker; `"0"` (string key) and `[0]` (array index) are
  distinct everywhere.
- **Shared-surface change (backward-compatible):**
  `formatting.search_block` gained `collection_complete: bool = True` so
  Stage 3 can honestly render `collection_complete=false`; every
  existing call site keeps byte-for-byte output (default unchanged).
- Files: `src/mcquest_mcp/tools/locales.py` (new),
  `src/mcquest_mcp/tools/__init__.py`, `src/mcquest_mcp/server.py`,
  `src/mcquest_mcp/formatting.py`, `tests/test_locale_inspect.py` (new,
  39 tests), `tests/test_discoverability.py` (+1),
  `tests/test_registration.py` (18→19, rename only).
- Verified: py_compile clean; focused Stage 3 suite
  `tests/test_locale_inspect.py` 39/39; focused regression set (locale +
  discoverability + registration + search + token_sparse) **143
  passed**; full regression **383 passed, 1 skipped** (Stage 2 record
  342 passed, 1 skipped; +40 new Stage 3 tests + 1 pre-existing
  suite-count delta; no pre-existing test modified except renaming the
  registration-count test 18→19).
- Scope boundaries preserved: no `mcquest_find_ui_strings` (Phase 3
  RESERVED / NOT AUTHORIZED), no V0.5/V0.6/runtime changes, no language
  expansion, no execution tools, Stages 4–5 PLANNED / NOT AUTHORIZED.
- D1 hold unchanged: no commit, no push.
