## 1. Testing philosophy

```text
Tool existence  ≠  acceptance.
Tool schema     ≠  behaviour.
Documentation   ≠  measurement.
```

v1.0's central claim is about **client behaviour** ("structured tools are preferred over
shell"). Therefore the suite has two distinct halves:

| Half | What it verifies | Can the server verify it? |
| --- | --- | --- |
| **Static** (§3–§5) | The tools are read-only, bounded, deterministic, well-registered | **Yes** |
| **Behavioural** (§6) | A live client actually routes correctly | **No** — requires an external harness |

A green static suite with an unmeasured behavioural half is **not** v1.0 acceptance.

## 6. Behavioural tests — the v1.0 acceptance model

> **These are the tests that define v1.0 acceptance.** They require a live client and an
> external observer. They are **not** automatable from inside the MCP server, because the
> server cannot observe which tool the client selects (contract §5.3).

### Test A — exact heading lookup

| Field | Value |
| --- | --- |
| Request | "Find `## 13.` in the specified Markdown document." |
| Expected route | a structured **search** tool (`mcquest_search_docs`, or `mcquest_file_find` if built) |
| **Forbidden** | PowerShell `Select-String`, `findstr`, `Get-Content` + pipeline |
| Pass | a structured search tool is selected; no shell command is issued |
| Evidence to record | the selected tool name, verbatim |

> The metacharacter `.` in `## 13.` must be handled as a **literal** (contract §4.1), not as
> a regex wildcard.

## 7. Harness requirements (P3, not yet authorized)

| Requirement | Detail |
| --- | --- |
| Observer | An **external** process/session that records which tool was invoked |
| Isolation | One scenario per session to avoid cross-contamination |
| Recording | Verbatim tool name + whether any shell command was issued |
| Negative results | A scenario that cannot be observed is recorded `UNKNOWN`, **never** assumed passed |
| Non-interference | The harness observes only; it never blocks, rewrites, or intercepts |
| Repeatability | Each scenario run at least twice; disagreement is recorded, not averaged |

> **Honesty rule.** If the observer cannot distinguish "the client chose a structured tool"
> from "the client chose shell", the result is `UNKNOWN`. It must not be reported as a pass.
