## 2. Snapshot vs normative — the rule

> **SNAPSHOT** = an observation with a timestamp. It can become wrong without anyone making a
> mistake. It must never be cited as a rule.
>
> **NORMATIVE** = a requirement. It stays in force until explicitly changed by a decision.

| Claim | Kind | Where it may be cited |
| --- | --- | --- |
| "34 tools are live at HEAD `e69bc1d`" | **SNAPSHOT** | Baseline context only |
| "960 passed, 1 skipped on 2026-09-29" | **SNAPSHOT** | Regression reference only |
| "A JSON value read must use a JSON tool" | **NORMATIVE** | Binding |
| "Routing must be measured, never asserted" | **NORMATIVE** | Binding |
| "No write primitive may exist in `src/`" | **NORMATIVE** | Binding |
| "`mcquest_locale_inspect` is locale-scoped" | **SNAPSHOT** (observed) | Rationale, not a rule |
| "Gap G1 exists" | **SNAPSHOT** | Re-verify before relying on it |

> **Consequence.** If a future phase changes the tool count, `02` and `05` are **not**
> automatically wrong — they are dated snapshots. Only `01`, `03`, and accepted entries in
> `07` carry binding force.
