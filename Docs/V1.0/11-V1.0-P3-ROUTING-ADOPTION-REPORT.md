## 0. Method, and the one limitation that must be read first

### 0.1 What P3 measures

P2 proved the **server** says the right things. P3 asks whether the **client** does them.

> **"the server says it" ≠ "the client does it"**

This report therefore counts **selected tools**, not instruction text. No result below is
inferred from P2's strings.

### 0.2 Self-observation limitation [UNKNOWN factor — read before using M1–M5]

**The live client performing these scenarios is the same agent that wrote the P2 guidance.**

| Consequence | Handling |
| --- | --- |
| I cannot be an independent observer of my own routing | Every routing-reason field is `UNKNOWN`; no self-reported reasons are claimed |
| I know the guidance text, which may prime compliant behaviour | Recorded as a **confound**, not corrected — no way to blind myself |
| Single session, no repetition | No rate, trend, or significance is claimed |

**Consequence for the metrics:** M1–M5 in §6 are **descriptions of one observed session**.
They must not be read as adoption rates, and P1-vs-P3 is **not a controlled experiment** —
the two sessions differ in agent, context, and the presence of the P2 text.

### 0.3 Discipline

Same seven scenario classes and same intent as P1. No redesign to obtain a favourable result.
Two unavoidable differences are recorded in §1 (target) and §3 (search root).

### P3-F1 — Native search is NOT a universal out-of-root branch [CONTRADICTS P2]

P2's contract says out-of-root local files should use the host's native tools
(`read_files`, `search_codebase`). P3 measured a **new limit** on that claim:

| Tool | Out-of-root behaviour | Evidence |
| --- | --- | --- |
| `read_files` | **Reached the target** | returned `Phase-66-…md:1425-1435` |
| `search_codebase` | **Did NOT reach the target** | `^##\s+13\.` → 6 results, **all** in `mcquest-mcp/`; searched 206 files |

**Consequence:** for an out-of-root target, the native *read* branch is available but the
native *search* branch appears workspace-scoped. In Scenario A the heading was located by
**reading** and inspecting, not by searching. The path to a correct answer existed, but it was
**narrower than P2 documents**.

> P2's §5.4a.1 left native scope `UNKNOWN` and refused to invent it (D-V1-11). That decision
> is what made this gap visible. Had P2 asserted native symmetry, this would have been hidden.

## 12. One-paragraph summary

P3 measured the same seven request classes against the live client after P2. Shell misuse
remained at **0 of 7** — unchanged, because there was none to fix. One scenario genuinely
improved: the client used P2's scope text to set an explicit search root, turning a confusing
9-vs-80 discrepancy into a clean 92-match answer. Two findings cut against P2's optimism: the
client still issued an out-of-root probe to MCQuest **before** routing natively, despite
instructions that explicitly forbid it; and the native `search_codebase` tool did **not** reach
an out-of-root target, contradicting P2's claim that native tools are a general out-of-root
branch. The P1 git-routing defect reproduced verbatim. No scenario failed for a missing tool,
so V1.0 still needs **zero** new MCP tools — but the honest conclusion is that P2's guidance is
**adopted partially, not reliably**, and the highest-leverage remaining action (a client-side
read rule) remains outside this repository.
