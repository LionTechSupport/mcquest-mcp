- **Allowed changes:** new files under `Docs/V0.9/` only.
- **Prohibited changes:** anything under `src/`, `tests/`, `pyproject.toml`, `README.md`; registering

- **Dependencies:** none (proposal + audit complete).
- **Tests:** none — documentation-only; no test run is claimed as evidence.
- **Exit criteria:** the ten-document package exists; proposal hash unchanged; `src/`/`tests/`
  unchanged; `git status --short` shows only documentation additions.
- **Authorization boundary:** **AUTHORIZED**.
- **Status:** COMPLETE.

## 3. P1 — State foundations

- **Objective:** implement the state vocabulary and memory: scopes, freshness, source/trust, the
  in-memory store, invalidation with revisions, terminal identity, and the cost table.
- **Allowed changes:** new `src/mcquest_mcp/shell/` package (`facts.py`, `store.py`,
  `invalidate.py`, `terminal.py`, `cost.py`, `__init__.py`); new test modules.
- **Prohibited changes:** no `server.py` edit, no tool registration, no modification of existing
  V0.8 modules, no filesystem writes, no new dependency, no output-path change to existing tools.
- **Dependencies:** P0.
- **Tests:** scope/freshness classification; source/trust defaults (`CWD: unknown / untrusted`);
  corroboration upgrades trust but not source; no cross-session or cross-process promotion;
  restart discards SESSION/PROCESS facts; invalidation table coverage and revision bumping;
  reuse allowed only when scope + identity match and nothing invalidated; cost classification
  determinism; read-only invariant still enforced by the existing no-write-primitives test.
- **Exit criteria:** all P1 tests pass; the existing suite stays at its baseline (`549 passed,
  1 skipped` for tool-level tests, since no tool changed); zero write-capable primitives in new code.
- **Authorization boundary:** requires explicit approval before starting.

## 4. P2 — Environment + capability discovery

- **Objective:** assemble the Environment Contract with source/trust labels and expose the capability
  registry with intent metadata, then register the first four tools.
- **Allowed changes:** `shell/environment.py`, `shell/capabilities.py`; `tools/shell_env.py`;
  `tools/__init__.py` exports; `server.py` registration of 4 tools; registration test update
  (24 → 28); new test modules.
- **Prohibited changes:** no modification of existing tool functions/schemas; no new dependency; no
  arbitrary command execution (approved probes only); no client-fact fabrication.
- **Dependencies:** P1.
- **Tests:** degraded mode with nothing declared; declared CWD trust transitions; probe results
  labeled `SERVER_OBSERVED` and shell baselines labeled as machine capability, never as the client's
  shell; registry exact-set equality with `EXPECTED_TOOLS`; live-server equality
  (`list_tools()`); intent-tag enum validity; deterministic ordering.
- **Exit criteria:** 28 registered tools; drift tests green; environment output stable byte-for-byte
  across repeated calls.
- **Authorization boundary:** requires explicit approval before starting.

---

## 5. P3 — Pure analyzers

- **Objective:** implement the analysis layer as pure, dependency-free functions over command text
  and facts.
- **Allowed changes:** `operations.py`, `dialect.py`, `native.py`, `parse.py`, `encoding.py`,
  `hazards.py`, `hygiene.py`, `redundancy.py`; new test modules.
- **Prohibited changes:** no tool registration; no `server.py` change; no I/O inside analyzers; no
  parser/AST dependency; no fuzzy similarity logic.
- **Dependencies:** P1 (facts), P2 (capability intent metadata for routing tests).
- **Tests:** operation classification (14 categories, including structured-data vs text);
  `>nul` in PowerShell; `chcp 65001 >nul`; native boundary for `findstr`; parse incompleteness
  (unmatched quote/paren, dangling pipe, unclosed block, trailing backtick, `>>`) with the three
  frozen verdicts; encoding/rendering separation; stale-variable and exception-unsafe hazards;
  hygiene/mutation detection; redundancy levels n0–n3 including the documented non-normalized cases.
- **Exit criteria:** every analyzer has an independent test module; outputs deterministic; no
  analyzer performs I/O; no false "complete" verdict is possible by construction.
- **Authorization boundary:** requires explicit approval before starting.

## 6. P4 — Validate + observe

- **Objective:** compose the analyzers into one deterministic validation report and add the
  observation/ingestion entry point.
- **Allowed changes:** `shell/validate.py`, `shell/planner.py` helper if needed by validate only;
  `tools/shell_env.py` (+2 functions); `tools/__init__.py`; `server.py` registration (28 → 30);
  registration test update; new test modules.
- **Prohibited changes:** no execution of the validated command; no mutation of any kind; no analyzer
  behavior change to make validate pass; no new dependency.
- **Dependencies:** P1, P2, P3.
- **Tests:** fixed section order and verdict tokens (`ERROR/WARNING/INFO/PASS`); leading
  machine-readable `[SUMMARY]`; byte-identical repeated output; budget compliance (4000/16000/200);
  no "valid"/"proven" verdict anywhere; `mcquest_shell_observe` applies invalidation to the mapped
  scope only; ingested tool evidence labeled `SERVER_OBSERVED` and process-scoped ingestion rejected
  without a declared client identity; `shell_lint` behaves as a mode, not a separate tool.
- **Exit criteria:** 30 registered tools; validation report deterministic and budget-compliant;
  read-only invariant tests green.
- **Authorization boundary:** requires explicit approval before starting.

## 7. P5 — Plan / prepare / history / next

- **Objective:** make the system actionable: classify intent, plan the minimum viable interaction,
  route to existing MCQuest capabilities, prepare a command as text, and choose a differentiated next
  action after failure.
- **Allowed changes:** `shell/planner.py` (operation → plan), `tools/shell_env.py` (+4 functions);
  `tools/__init__.py`; `server.py` registration (30 → 34); registration test update; new test modules.
- **Prohibited changes:** no autonomous execution; no enforcement/denial behavior; no mutation; no
  bypassing the store for history; no fuzzy command equivalence.
- **Dependencies:** P1–P4.
- **Tests:** planner preference order (existing evidence → existing capability → structured tool →
  targeted shell → broad scan); capability routing for intents answerable by a V0.8 tool;
  `mcquest_shell_prepare` output labeled as not executed; redundancy levels n0–n3 incl. documented
  non-normalized cases; blind-retry prevention when nothing changed and differentiated recovery when
  something did; `mcquest_shell_history` paging determinism.
- **Exit criteria:** 34 registered tools; routing and blind-retry tests green; no execution path
  exists in the codebase.
- **Authorization boundary:** requires explicit approval before starting.

## 10. Cross-phase rules

1. Every phase begins only after explicit approval of the previous phase's exit criteria.
2. No phase may modify an existing V0.8 tool, its schema, or its output.
3. No phase may add a third-party dependency.
4. No phase may introduce repository mutation or arbitrary command execution.
5. No phase may modify `MCQuest_V0.9_Master_Proposal.md`.
6. Any new architectural decision discovered during a phase is recorded in `07-V0.9-DECISIONS.md`
   before being implemented.
7. Reporting must distinguish approved decisions from implemented functionality.
