## 3. The central observability constraint (must not be designed around)

**The MCP server process cannot directly observe Cline's terminal session.**

The server is a separate process launched by the client. It has its own CWD, environment, process
id, console code page, and shell. It cannot read the client shell's CWD, latest exit code, variables,
or PSReadLine state.

Consequences recorded by this audit (and now governed by decision **A2**):

- the server's own CWD / PID / console page must never be presented as Cline's terminal facts;
- `CWD` starts as `value: unknown`, `source: UNKNOWN`, `trust: untrusted`;
- terminal session id, client process id, client shell version, client environment variables, and
  client console code page are unknowable unless the client declares them;
- no fact may be promoted across sessions or processes.

## 10. Required tests (behavior, not implementation detail)

**State and environment**

- CWD defaults to `unknown` / `UNKNOWN` / `untrusted`;
- an explicit repository path is required when the CWD is untrusted;
- a session-A observation is never reused in session B;
- process restart invalidates PROCESS-scope facts;
- `Set-Location`, file write, and git checkout invalidate only their mapped scopes.

**Analyzers**

- `>nul` in PowerShell → cross-shell WARNING (benchmark 5, 15);
- `chcp 65001 >nul` → mutation + encoding WARNING (benchmark 5);
- `findstr /n /c:` → native-boundary WARNING (benchmark 6);
- unmatched quote/paren, dangling `|`, unclosed `{`, trailing backtick, `>>` → parse verdict
  `INCOMPLETE (DETECTED, heuristic)`, classified as parse incompleteness, never an execution failure
  (benchmark 7);
- `$bytes = [IO.File]::ReadAllBytes(...)` followed by dependent output → stale-variable hazard
  (benchmark 9);
- mojibake terminal rendering plus a successful structured read → rendering ≠ source corruption
  (benchmark 10);
- `Get-ChildItem -Recurse | Select-String` → HIGH/VERY HIGH cost and routing to `mcquest_search` /
  `mcquest_doc_gap_audit` (benchmarks 4, 11, 12);
- a JSON key lookup via text search → operation SUBOPTIMAL with a `READ_JSON` recommendation
  (benchmark 14);
- a repeated identical command with no changed condition → duplicate/blind-retry refusal with a
  differentiated `mcquest_shell_next` (benchmarks 2, 3, 13).

**Invariants**

- zero write-capable primitives in new source (the existing no-write-primitive test extends to the new
  package automatically);
- every new tool has per-parameter descriptions and a non-empty docstring;
- output ≤ 4000 characters by default, ≤ 16000 maximum, line clip ≤ 200 characters;
- repeated calls produce byte-identical output;
- `collection_complete` / incomplete-collection `NOTE` semantics for any bounded scan;
- exactly one registration-count assertion changes per phase, to the approved number.
