## 2. What V0.9 is

> **Environment + Terminal + Shell + Command Intelligence for Cline.**

The three-way separation is fixed and must not be reinterpreted:

```text
MCQuest V0.8   Repository Intelligence                  "What is true?"
MCQuest V0.9   Environment + Terminal + Command Intel.   "How should I interact with it?"
Cline          Task Intelligence                         "What should I accomplish?"
```

V0.9 is therefore **not** a repository auditor, **not** a generic AI shell assistant, and **not**
a shell executor. It is an intelligence layer over the environment in which repository work happens.

## 3. Approved scope

Approved MVP scope (proposal §34, confirmed by this authorization):

| Area | Content |
| --- | --- |
| Platform | Windows, PowerShell (5.1 **and** 7 per A8), Git, Node.js-aware workflows |
| Core environment | Environment Contract, terminal/process identity, observation store, scope and freshness, invalidation, compact shell context |
| Core planning | semantic operation classification, minimal command planning, MCQuest capability routing, command preparation |
| Core validation | CWD trust, relative-path dependence, shell dialect, native-command boundaries, parse completeness, duplicate commands, broad scans, unnecessary environment mutation, encoding/rendering risk, exception-unsafe calculations, stale-variable hazards, cost classification |

### Approved non-goals (unchanged from proposal §34)

- autonomous shell execution;
- automatic repository modification;
- vector database;
- broad cross-platform abstraction;
- replacing V0.8 audit tools.

## 4. V0.8 / V0.9 boundary

| | MCQuest V0.8 | MCQuest V0.9 |
| --- | --- | --- |
| Question | "What is true?" | "How should I interact with it?" |
| Domain | repository intelligence | environment, terminal, shell, command intelligence |
| Tools | 24 registered `mcquest_*` tools | 10 approved `mcquest_shell_*` tools (none registered yet) |
| Maturity | shipped | documentation baseline only |
| Mutation | none (read-only) | none (recommend-only) |

Binding boundary rules:

1. V0.9 **reuses** existing repository intelligence rather than recreating it through PowerShell.
2. V0.9 **must not duplicate** a V0.8 capability; when an existing capability answers the intent,
   V0.9 routes to it (decision A12).
3. V0.9 **must not modify** existing V0.8 source, tool schemas, or output.
4. Existing V0.8 scanners are not to be extended, refactored, or repaired as part of V0.9 work.
