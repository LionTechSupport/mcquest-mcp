---

## 1. Strategy

1. Test-first: each behavior is identified before the code that satisfies it (test-first expectation,
   V0.9 execution instruction §34).
2. One test module per analyzer/component, mirroring the V0.8 convention of one module per tool.
3. Pure-function analyzers are tested directly, without executing any shell.
4. State tests always reset the in-memory store so no test leaks state into another.
5. No test may execute a client command, mutate the repository, or require a specific host shell.
6. Determinism is asserted where required (byte-identical repeated output).
7. Negative results are bounded: a test asserts
   `NO INCOMPLETENESS DETECTED (heuristic)` — never "valid".
8. Reporting rule: a test result may only be reported after the test is actually executed.

---

## 2. Deterministic-output requirements

| Requirement | Assertion |
| --- | --- |
| Repeated identical calls | byte-identical output |
| Ordering | findings ordered by a documented deterministic key |
| Clock independence | no expiry/validity behavior depends on wall-clock time |
| Locale independence | output does not vary with host locale or console code page |
| Collection status | `collection_complete` semantics preserved for any bounded scan |
| Incompleteness note | an incomplete-collection `NOTE` appears only when a cap is actually hit |

---

## 3. Output budget requirements (existing formatting contract)

```text
default <= 4000 characters
maximum <= 16000 characters
line clip <= 200 characters
```

Applies to every V0.9 tool, including validation output. Tests assert each bound, and assert that a
bounded scan reports its truncation rather than silently dropping evidence.
